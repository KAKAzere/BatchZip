# BatchZip v1.0.0-rc4

BatchZip v1.0.0-rc4 is a release candidate focused on reliability, process lifecycle handling, warning recovery, build consistency, and Windows packaging stability.

This release contains substantial improvements since `v1.0.0-rc3`, including stronger 7-Zip process management, dedicated warning handling, safer archive cleanup, reproducible dependency locking, and a hardened PyInstaller build environment.

---

## ✨ Highlights

### Better 7-Zip process lifecycle management

BatchZip now manages each compression process through a dedicated Windows Job Object.

This means:

- Each BatchZip instance manages only its own 7-Zip process.
- Force-closing BatchZip also terminates the 7-Zip process started by that instance.
- Other BatchZip instances remain unaffected.
- Manually started or third-party 7-Zip processes remain unaffected.

This improves cleanup and prevents orphaned compression processes after unexpected application termination.

---

### Improved warning handling

7-Zip warning results are now handled separately from successful and failed compression tasks.

When an archive is created with warnings, BatchZip now:

- Shows a dedicated warning state.
- Identifies affected files where possible.
- Presents a concise English explanation.
- Allows the user to choose whether to keep or delete the incomplete archive.
- Keeps warning results separate from failures in completion statistics.

Available actions:

- **Keep Archive**
- **Delete Archive**

If deletion fails, BatchZip clearly reports the remaining archive path.

---

### More reliable cancellation and cleanup

Cancellation handling has been strengthened.

BatchZip now:

- Confirms the active 7-Zip process has actually stopped before marking a task as cancelled.
- Attempts termination first and escalates when necessary.
- Removes incomplete archives after confirmed cancellation.
- Reports cleanup failures instead of silently ignoring them.
- Prevents the application from waiting indefinitely during shutdown.

---

### Reproducible build environment

The Windows build process has been significantly improved.

Release builds now use:

- Python 3.14.7 64-bit
- An isolated `.venv`
- Exact direct dependency versions
- A complete `requirements-lock.txt`
- Dependency integrity checks
- Environment drift detection
- A fixed PyInstaller version

The build process verifies that the virtual environment exactly matches the locked dependency set before packaging.

Unexpected, missing, or mismatched packages stop the build.

---

### Hardened PyInstaller build isolation

A packaging issue was identified where external native DLL directories in the parent process `PATH` could influence PyInstaller dependency discovery.

This could cause incompatible DLLs from unrelated software to be included in BatchZip.

In one confirmed case, an incompatible ICU library was collected and caused:

```text
ImportError: DLL load failed while importing QtGui
```

The build process now creates a controlled Windows system `PATH` before PyInstaller dependency analysis.

This prevents unrelated native libraries from leaking into BatchZip release builds.

- Fixed 7-Zip processes remaining alive after BatchZip was forcibly terminated.
- Fixed cancellation being reported before the underlying 7-Zip process was fully stopped.

- Fixed warning results being treated the same as fatal compression failures.
- Fixed ambiguous completion messages when warnings were present.

- Fixed duplicated and noisy diagnostic information in warning dialogs.

## 📦 Requirements

### Packaged EXE

- Windows 10 or Windows 11
- 7-Zip installed on the computer

Python is not required when using the packaged executable.

BatchZip does not redistribute 7-Zip.

### Running from source

- Windows 10 or Windows 11
- Python 3.14.x
- 7-Zip
- Dependencies listed in `requirements.txt`

Official release builds use:

```text
Python 3.14.7 64-bit
```

## 📂 Output Naming

BatchZip avoids silently overwriting existing archives by generating unique output names.

For example:

```text
report.zip
report (2).zip
report (3).zip
```
