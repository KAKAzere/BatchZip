# BatchZip v1.0.0-rc5

BatchZip v1.0.0-rc5 is a release candidate focused on the task-queue architecture, compression-session state correctness, and recovery when a compression worker cannot be started.

This release contains substantial changes since `v1.0.0-rc4`. The production task queue has been migrated to an authoritative model/view/delegate architecture, two user-visible defects in compression-session state have been fixed, and the application has been re-validated end to end from source and as a packaged executable.

---

## ✨ Highlights

### Authoritative task-queue architecture

The production task queue has moved from a widget-per-row list to a model/view/delegate architecture.

The queue model is now the single source of truth for which tasks are queued, in what order, and with which identity. The view handles interaction only, and task rows are painted directly by a delegate instead of being built as individual widgets.

This means:

- One authoritative task order shared by the List and Grid layouts.
- Reordering moves rows through the model, so task identity is preserved and no model reset occurs.
- Deleting and reordering continue to behave as before.
- The queue is locked against reordering and deletion while a compression session is running.
- No per-row widgets are created for queued tasks.

The legacy per-item card widget path has been removed from production.

---

### Correct pause presentation across session restarts

A user-visible defect has been fixed.

Previously, this sequence could leave the interface in the wrong state:

```text
Start -> Pause -> Cancel -> Start again
```

The new session would begin compressing while the queue still displayed `Paused`.

BatchZip now reports the new session as `Compressing` immediately, and pause presentation is synchronized from a single place in the compression-session lifecycle.

---

### Safe recovery when the compression worker cannot start

Starting a compression creates a background worker. If that worker could not be started, BatchZip could previously remain in a compression state with the queue locked, the controls disabled, and no way to continue from the interface.

BatchZip now:

- Rolls the compression session back.
- Restores the start controls.
- Clears the failed worker reference.
- Reports the failure together with the underlying reason.
- Allows the user to try again without restarting the application.

---

### Large end-to-end validation pass

RC5 has been validated at three levels: the automated regression suite, the real production source path, and the packaged executable.

See **Testing** and **Windows Validation** below.

## 🆕 Added

- A dedicated task-queue model as the authoritative source of task membership, ordering, and identity.
- A task-queue delegate that paints task rows directly without constructing a widget per row.
- A task-queue runtime controller connecting the production window to the queue model.
- List and Grid layouts that render one shared authoritative task order.
- Queue interaction locking for the duration of a compression session.
- Single-entry compression-session state seams for the active and paused states.
- Rollback and recovery when the background compression worker fails to start.
- Regression coverage for the queue architecture, compression-session state, and worker-start failure.

---

## 🔄 Changed

- The production window now drives the task queue through the model/view/delegate path.
- Compression-session state and pause presentation are updated through single-entry seams.
- Task progress, status, and warning presentation continue to be derived from the task model.
- Removed the legacy per-item task card production path.
- Removed the orphaned `Task.compact` field.
- Replaced the drop-zone queue-count API with a prompt-reset API.

---

## 🐛 Fixed

- Fixed a new compression session being displayed as `Paused` after pause, cancel, and restart.
- Fixed a worker-start failure leaving the session active, the queue locked, and the controls disabled.
- Fixed queue-lock and pause presentation being updated independently of the compression-session state.

## 🖥️ Windows Validation

In addition to the automated suite, this source state has been validated end to end on Windows 11 through the real production path: the real application window, the real background compression worker, and a real 7-Zip 26.03 installation located by BatchZip's own 7-Zip detector.

Verified:

- ZIP compression
- 7Z compression
- Files and folders
- Unicode file and folder names
- Paths containing spaces
- Nested folder trees
- Empty files and empty folders
- Existing archive name conflicts
- Pause and resume of a 256 MiB compression
- Cancellation
- Partial archive cleanup after cancellation
- Cancellation followed by a new session
- Warning handling
- Keep Archive
- Delete Archive
- Failed task handling
- Archive integrity, checked by testing each archive, extracting it, and comparing SHA-256 hashes
- Clean shutdown with no leftover application or 7-Zip processes

The packaging configuration and the behavior of the packaged application were validated as well:

- Single-file (`ONEFILE`) executable built from the current working tree
- Launch outside the repository folder
- Launch from an unrelated working directory

- Real ZIP and 7Z compression from the packaged executable
- Pause, resume, and cancellation from the packaged executable
- Cancellation followed by a new session from the packaged executable
- Completion dialog
- 7-Zip started as a child process of the packaged application
- Temporary extraction directory created at startup and removed on exit
- Clean process exit with no leftover processes

Packaging configuration and behavior were validated before the final RC5 rebuild.

## 📦 Requirements

### Packaged EXE

- Windows 10 or Windows 11
- 7-Zip installed on the computer

Python is not required when using the packaged executable.

BatchZip does not redistribute 7-Zip.

### Running from source

- Windows 10 or Windows 11
- Python 3.14.x
- 7-Zip
- Dependencies listed in `requirements.txt`

Official release builds use:

```text
Python 3.14.7 64-bit
```

## 📂 Output Naming

BatchZip avoids silently overwriting existing archives by generating unique output names.

For example:

```text
report.zip
report (2).zip
report (3).zip
```
